# Памятка к защите лабораторной работы № 3

## Что делает программа

Программа получает путь к бинарному файлу, читает из него полётные записи, преобразует их в односвязный список и строит по высотам бинарное дерево поиска. По самому левому и самому правому узлам дерева она получает минимальную и максимальную высоты. Затем программа считает количество точек и продолжительность маршрута, выводит результат и сохраняет его в `output/statistics.txt`.

## Основные понятия

- **Бинарный файл** хранит данные в виде байтов, а не читаемого текста. Его удобно читать строго по структуре записи.
- **Одна запись** состоит из `uint32_t timestamp_ms`, `float lat_rad`, `float lon_rad`, `float alt_m`.
- **16 байт** получаются как 4 + 4 + 4 + 4: все четыре поля имеют размер 4 байта на используемой платформе.
- **uint32_t** — беззнаковое целое число ровно на 32 бита. Оно подходит для отметки времени в миллисекундах.
- **float** — вещественное число одинарной точности; здесь им хранятся координаты и высота.
- **Указатель** хранит адрес объекта в памяти. Он позволяет связать элементы списка и дерева.
- **Динамическая память** выделяется во время работы программы функцией `malloc`. Она нужна, когда заранее неизвестно точное число записей.
- **Односвязный список** — последовательность узлов. В каждом узле есть полётная точка и поле `next`, то есть адрес следующего узла.
- **Зачем `next`**: по нему программа переходит от текущей точки к следующей; у последнего узла `next == NULL`.
- **Список и массив**: список удобно наращивать без заранее известного размера, но доступ к элементу по номеру требует прохода с начала. У массива доступ по индексу быстрый, но размер и расширение менее удобны.
- **Бинарное дерево поиска**: для каждого узла все меньшие высоты находятся слева, все большие — справа.
- **Почему минимум слева, максимум справа**: переходя только влево, мы всё время выбираем меньшую высоту; последний левый узел — минимум. Аналогично справа находится максимум.
- **Вставка в дерево**: новая высота сравнивается с текущей; меньшая идёт в левое поддерево, большая — в правое. Ровно совпадающая высота не добавляется повторно: на min/max это не влияет.
- **Рекурсия** удобна для вставки и освобождения дерева: функция выполняет одинаковое действие для левого и правого поддерева.
- **Продолжительность** вычисляется как `(last_timestamp_ms - first_timestamp_ms) / 1000.0` и получается в секундах.
- **Радианы переводятся в градусы**, поскольку градусы привычнее при просмотре географических координат: `deg = rad * 180 / π`.
- **argc и argv**: `argc` — число аргументов командной строки, `argv` — их массив. `argv[1]` хранит путь к файлу, если пользователь его указал.
- **fread** читает указанное число байтов из уже открытого файла в структуру `BinaryRecord`.
- **free** освобождает память, выделенную через `malloc`. В программе освобождаются и список, и дерево.
- **Git** — распределённая система контроля версий. Она хранит историю изменений, позволяет работать с ветками и объединять изменения нескольких разработчиков.
- **Makefile** содержит правила сборки. Команда `make` собирает программу, `make run` запускает её, `make clean` удаляет каталог сборки.

## Вероятные вопросы преподавателя

1. **Почему данные считываются бинарно?** Потому что исходный файл содержит структуры в байтовом представлении, а не строки текста.
2. **Как проверяется формат файла?** Программа читает запись размером 16 байт и проверяет, что размер файла кратен размеру записи.
3. **Что будет, если файл не откроется?** `fopen` вернёт `NULL`, программа выведет системную причину ошибки и завершится.
4. **Почему список односвязный?** Для задачи достаточно перехода только вперёд; это уменьшает число указателей в узле.
5. **Как добавляется элемент в конец?** Поле `tail` хранит адрес последнего узла, поэтому новый узел добавляется за постоянное время.
6. **Почему узлы списка создаются динамически?** Количество записей определяется содержимым файла, а не задаётся заранее.
7. **Как программа не теряет первый элемент?** В структуре `FlightList` хранится указатель `head` на первый узел.
8. **Что хранится в последнем узле?** Данные последней точки, а его `next` равен `NULL`.
9. **Почему высоты помещаются в BST?** Свойство упорядоченности BST позволяет найти минимум и максимум простым проходом по одной ветви.
10. **Что происходит с одинаковой высотой?** Точная копия не вставляется. Для вычисления минимума и максимума она ничего не меняет.
11. **Почему нельзя просто искать min/max в списке?** Можно, но по заданию требуется использовать свойства бинарного дерева; программа строит и применяет BST.
12. **Какова сложность поиска min/max в дереве?** O(h), где h — высота дерева; нужно пройти только левую или правую ветвь.
13. **Какова сложность вставки?** O(h); в среднем для достаточно сбалансированного дерева близка к O(log n).
14. **Опасна ли рекурсия для освобождения?** Она завершится на `NULL`; для данного набора данных дерево имеет приемлемую высоту.
15. **Что означает `uint32_t`?** Тип из `<stdint.h>` с точно определённой шириной 32 бита.
16. **Почему время хранится в миллисекундах?** Это даёт точность 20 мс, которая есть в исходных измерениях.
17. **Как получены секунды?** Разность меток времени делится на 1000.0.
18. **Почему координаты переводятся в градусы?** Они лучше читаются человеком, тогда как радианы удобны для математических вычислений.
19. **Почему используется `float`, а не `double`?** Формат файла уже задаёт поля как 4-байтовые `float`; при чтении нужно ему соответствовать.
20. **Что делает `malloc`?** Выделяет запрошенный размер памяти в куче и возвращает её адрес.
21. **Зачем проверять результат `malloc`?** При нехватке памяти он вернёт `NULL`; запись по такому адресу привела бы к ошибке.
22. **Зачем нужен `free`?** Чтобы память, занятая узлами, стала доступна после завершения обработки.
23. **Что покажет `make run`?** Он соберёт программу при необходимости и запустит анализ файла `data/flight_data6.bin`.
24. **Для чего нужен `git status`?** Он показывает изменённые и новые файлы, а также состояние индекса.
25. **Чем `git add` отличается от `git commit`?** `git add` подготавливает изменения, а `git commit` сохраняет подготовленную версию в истории.
26. **Для чего нужна ветка?** Она позволяет вести независимую работу, не меняя основную линию разработки.
27. **Что делают `git pull` и `git push`?** `pull` получает изменения из удалённого репозитория, `push` отправляет туда локальные коммиты.
28. **Что делает `git log`?** Показывает историю коммитов.
